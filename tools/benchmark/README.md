# Astrometric accuracy benchmark

Measures, with public data, how well `piazzi` finds and measures known asteroids: ZTF images (IRSA), the Gaia DR3
catalog, identification by IMCCE SkyBoT, and ground truth from JPL Horizons. Python 3 standard library only.

```sh
# from the repository root
python3 -I tools/benchmark/run.py select --n 30           # (re)generates fields.json — only when you want to change the sample
python3 -I tools/benchmark/run.py run --label base --piazzi cpp/build/piazzi
python3 -I tools/benchmark/run.py run --label new --piazzi /other/build/piazzi
python3 -I tools/benchmark/run.py compare tools/benchmark/results/base.json tools/benchmark/results/new.json
python3 -I tools/benchmark/run.py summary tools/benchmark/results/base.json
```

`run` options: `--only ID1,ID2`, `--max N`, `--fields other.json`.

The kept results are listed in [`results/README.md`](results/README.md).

## How it works

* **`fields.json` (versioned)** — fixed list of sequences generated by `select`: random points (fixed seed) near the
  ecliptic, a query to the ZTF index at IRSA, grouping of ≥3 exposures of the same quadrant
  (field/ccd/qid) within a ≤3 h window with an arc ≥30 min (filters may be mixed: ZTF rarely takes ≥3 exposures
  in the same filter per night), and a SkyBoT target with V 15–20 (max. 7 per integer magnitude). Stores the target and
  all known SkyBoT objects in the cutout (to associate tracks and count false positives).
* **`run`** — per sequence: 12′ cutouts centered on the target's mean position (cached), Gaia DR3 catalog for the box
  printed by piazzi itself (VizieR; if VizieR fails, the same box via the NOIRLab Astro Data Lab TAP,
  converted to VizieR TSV), piazzi with `focal_length_mm=3063 pixel_width_mm=pixel_height_mm=0.015 mpc_code=I41 time_reference=0`.
  Timing: IRSA cutouts have no `DATE-OBS`; they have `OBSJD` (= UTC-OBS, **start** of exposure) and `EXPTIME`=30 s.
  piazzi uses `OBSJD` and, with time_reference=0 (start), adds EXPTIME/2 — the ADES `obsTime` is mid-exposure.
* Each track in `ADESReport.psv` is associated with the SkyBoT object whose predicted position (linear, from SkyBoT
  position and velocity) is within < 10″ (median over the measurements). A track with no known object = false positive
  (it may also be an unknown/very faint asteroid or one missing from SkyBoT).
* O−C against Horizons (`CENTER='I41@399'`, `QUANTITIES=1` astrometric ICRF, `TLIST` = ADES instants in UT).

## Metrics (`results/<label>.json` and `.md`)

Number of sequences, data failures, unsolved plates (<6 refs), target detection rate (total and per V bin),
median / rms / p95 |O−C| and per axis (RA·cosδ, Dec), median ADES sigma (rmsRA⊕rmsDec), median |O−C|/sigma ratio
(≈1.2 would be well calibrated for 2D Gaussian error: Rayleigh median = 1.18σ), tracks with no known object per
sequence, time. Each measurement stores mag, logSNR, rmsRA/rmsDec.

## Comparison with official MPC astrometry (`vs-mpc`)

```sh
python3 -I tools/benchmark/run.py vs-mpc --label v9-dev                 # ZTF dev (fields.json)
python3 -I tools/benchmark/run.py vs-mpc --label nea-v9                 # NEAs (the --fields stored in the result)
```

Reads `results/<label>.json`, downloads the target's observations from the public MPC API (`get-obs`, GET with JSON body
`{"desigs": [...], "output_format": ["ADES_DF"]}`; cached in `cache/mpcobs/`, 2 s pause, retries) and, for each Piazzi
measurement, takes the observation from the same station (I41 = ZTF, 645 = SDSS) closest within |Δt| < 60 s. Both are
reduced against Horizons at **their own instants** and Δ = (P−H)(t_P) − (MPC−H)(t_MPC) (corrects for motion when the
times differ). It also stores the direct position comparison (both against Horizons at the Piazzi instant), which
ignores the MPC time label, and the MPC |O−C| at both instants — a diagnostic of the time label. Output:
`results/<label>-vsmpc.json/.md` with number of pairs, median/rms/p95 |Piazzi−MPC|, per-axis bias, Piazzi and
MPC |O−C| side by side (which is closer to Horizons), ADES σ of both, and a per-sequence table (with the reason when
there is no pair).

Results (v9, November 2026; files `results/v9-dev-vsmpc.*`, `results/nea-v9-vsmpc.*`, `results/sdss-v8-vsmpc.*`):

| set | pairs (seq.) | \|P−MPC\| med/rms/p95 | positions only med/rms/p95 | bias RA·cosδ/Dec | \|O−C\| med Piazzi / MPC | Piazzi closer |
|---|---|---|---|---|---|---|
| ZTF dev (v9-dev) | 7 (4) | 0.069/0.096/0.151″ | 0.054/0.058/0.084″ | +0.054/−0.010″ | 0.020 / 0.064″ | 7/7 |
| NEA dev (nea-v9) | 9 (3) | 0.484/0.509/0.697″ | 0.067/0.068/0.095″ | −0.464/+0.039″ | 0.095 / 0.512″ | 9/9 |
| SDSS (sdss-v8, held out, read-only) | 44 (22) | 0.054/0.098/0.194″ | 0.121/0.138/0.257″ | −0.003/−0.015″ | 0.033 / 0.083″ | 36/44 |

* **Few ZTF pairs**: ZTF only submitted to the MPC the nights of 7 of the 31 sequences with a Piazzi measurement (13 ZTF dev
  + 10 NEA with no I41 observation within ±1 h). Small sample.
* **ZTF time label**: in the 2019–2020 submissions the MPC `obstime` is 15.0 s **before** mid-exposure
  (= start), but the position is the mid-exposure one: the MPC |O−C| drops from 0.138″ to 0.071″ (MB) and from 0.512″ to
  0.102″ (NEAs) when evaluated at mid-exposure. In 2021 (Hindemith) the times agree (|Δt| < 0.3 s). For
  ZTF, the "positions only" metric is the fair comparison; the timed Δ is dominated by this time error for NEAs.
  With the ZTF time corrected to mid-exposure, Piazzi is still closer to Horizons in 5/7 (MB) and
  6/9 (NEA) pairs.
* **SDSS**: there are 645 observations at the MPC (UCAC1 catalog, precision 0.001 s/0.01″, no rmsRA/rmsDec). One MPC
  observation per epoch, while Piazzi measures each filter; the closest filter is 0.2–0.3 s or ~13 s away. Here the MPC
  times are correct (the timed Δ, 0.054″, is smaller than "positions only", 0.121″).
* ZTF publishes rmsRA/rmsDec (median σ 0.096″ MB, 0.160″ NEA) and catalog Gaia1 (Gaia DR1/DR2, proper motion not
  propagated the same way as Piazzi's Gaia DR3 — a likely part of the +0.05″ RA bias).

## Services

Retries with backoff, per-host pause (1–2 s), everything in `tools/benchmark/cache/` (in `.gitignore`); a sequence that
fails (cutout at the quadrant edge, service down) is recorded with `status`/`error` and the benchmark continues.

## Independent test set: SDSS (`fields_sdss.json`) — HELD OUT

`fields.json` (ZTF) is the **development** set. `fields_sdss.json` is a **test** set from another
instrument, held out for the final evaluation: do not tune anything in piazzi by looking at it.

```sh
python3 -I tools/benchmark/run.py select-sdss --out tools/benchmark/fields_sdss.json --n 38   # (re)generates; downloads and converts the frames
python3 -I tools/benchmark/run.py fetch --fields tools/benchmark/fields_sdss.json --piazzi cpp/build/piazzi  # cache (frames + Gaia)
python3 -I tools/benchmark/run.py run --fields tools/benchmark/fields_sdss.json --label sdss-final --piazzi cpp/build/piazzi
```

* **Data**: SDSS DR17 calibrated frames (`frame-<f>-<run6>-<camcol>-<field4>.fits.bz2`, data.sdss.org), 2.5 m
  telescope at Apache Point, MPC **645**, 0.396″/px, 2048×1489 px (13.5′×9.8′, full frame, no cutout). The camera is
  drift scan: the same field (run/camcol/field) passes through the filters in the order **r, i, u, z, g**, 71.7 s
  between adjacent filters; effective integration 53.9 s. One sequence = one field, frames in time order.
* **Filters used: r, i, z, g (4 epochs, 287 s arc)**. `u` is left out: it is shallow (~22.0 vs 22.2 in r, but
  asteroids have u−r ≈ 1.5–2 mag) and the instrumental magnitude calibrated against Gaia RP changes too much — the piazzi
  linker rejects tracks with amplitude > 1.5 mag and, with 5 frames, accepts only 1 missing. With 4 frames the linker also
  accepts 1 missing (e.g. a faint target that vanishes in the shallow z). `select-sdss --filters riuzg` generates the 5-epoch variant.
* **Timing (careful: drift scan)**: each row of the frame is exposed at a different instant. The header `TAI` is that of the
  1st row; mid-exposure for a point on row `y` is `TAI − EXPTIME/2 + y·EXPTIME/2048` (TAI in s since
  MJD 0), checked against the per-object `TAI_<f>`/`rowc_<f>` from photoObj in SkyServer (difference 0.08 s). UTC = TAI −
  (32 s until 2005, 33 s in 2006–2008, 34 s after). The time stored in each image is that of the **target's row** in that
  filter (iterating time ↔ Horizons position ↔ row via the WCS); other objects in the frame have time errors of up to
  ±20 s (irrelevant for the 10″ association).
* **Conversion** (stdlib `bz2`/`array`): nanomaggies → DN via the per-column calibration vector (HDU1) + sky (median of the
  ALLSKY grid in HDU2) → electrons via the approximate gain per filter/camcol (DR7 table) → integer 0–65535
  (BITPIX 16, BZERO 32768), `GAIN=1`, `DATE-OBS` = UTC of mid-exposure at the target's row, `EXPTIME`, original WCS.
  Stored in `cache/fits/sdss_*/` (≈6 MB each); the original `.bz2` files in `cache/sdss/raw/`.
* **piazzi settings**: `focal_length_mm=12501 pixel_width_mm=pixel_height_mm=0.024` (0.396″/px), `mpc_code=645`, `time_reference=1`
  (DATE-OBS is already mid-exposure), `catalog_faint_mag=20`, `saturation=60000`.
* **Selection** (`select-sdss`): sample of the SkyServer DR17 `Field` table (`field % 40 = 7`, `quality >= 2`), fields
  with |β| ≤ 12°, shuffled (seed 7); SkyBoT (`-loc 645`) within a 6.6′ radius at the r instant; target with V 15–21
  (max. 6 per integer magnitude, priority to the least-filled V and rate bins and to the fastest), inside
  the frame (60 px margin) in all filters according to Horizons; max. 2 sequences per run.
* **Truth**: Horizons `CENTER='645@399'` at the ADES `obsTime`s; known objects (association/false positives) from
  SkyBoT. Each sequence stores run/camcol/field, filters, per exposure the mid-exposure UTC JD, the target's predicted row/column,
  the 1st-row TAI, and the target (V, rate).
* **Note**: the arc is only ~5 min; a main-belt asteroid at 0.5″/min moves ~2.4″ (6 px). It is a hard test
  of motion detection (unlike ZTF, with 0.5–3 h arcs).
* **Current set** (32 sequences; `select-sdss --n 38 --probes 2500`, stopped at 32 for lack of bright
  targets): V 15–16: 2, 16–17: 6, 17–18: 6, 18–19: 6, 19–20: 6, 20–21: 6; rate < 0.3″/min: 3,
  0.3–0.6: 18, 0.6–1: 11 (no fast NEA appeared in the random sample); |b| 22°–70°. Check independent of
  piazzi: target centroid in the converted frames vs Horizons at the stored time: residuals ≤ 0.5 px (≤ 0.2″) with no bias
  along the motion (a half-exposure error, 27 s, would give ~0.7 px).

## Fast NEA development set (`fields_nea_dev.json`)

ZTF sequences of NEAs (1–30″/min, V 15–20) for iterating on fast-object detection **without touching** the blind test
`fields_test.json`. Generated by `select-targets --objects cad` (JPL CAD close approaches) with seeds and date ranges
different from the test's, in parallel processes later merged (no repeated id or field+night):

```sh
python3 -I tools/benchmark/run.py select-targets --objects cad --seed 101 --date-min 2018-03-01 --date-max 2019-12-31 \
  --n 6 --rate-min 1 --rate-max 30 --vmin 15 --vmax 20 --label nea_dev \
  --exclude tools/benchmark/fields_test.json --exclude tools/benchmark/fields.json \
  --exclude-objects "2020 FW4,2019 FT,2011 AG5,2023 PC1,2019 NX6,2019 FP2,2020 FA7,2020 BO1,2020 TY1,1990 MF" \
  --out /tmp/s101.json
```

`--exclude` (repeatable) avoids field+night and ids from those files **and** their targets (`target.name/num`);
`--exclude-objects` excludes designations explicitly; `--date-min/--date-max` change the CAD close-approach window.
